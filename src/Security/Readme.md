## How authentication works

`config/packages/security.yaml` wires the `main` firewall to a custom JWT authenticator:

````yaml
security:
    providers:
        app_user_provider:
            id: App\Security\Infrastructure\Symfony\UserProvider\AppUserProvider
    firewalls:
        main:
            lazy: true
            stateless: true
            provider: app_user_provider
            custom_authenticators:
                - App\Security\Infrastructure\Symfony\JwtAuthenticator
            entry_point: App\Security\Infrastructure\Symfony\JwtAuthenticator

    access_control:
        - { path: ^/login$, roles: PUBLIC_ACCESS }
        - { path: ^/token-renew$, roles: PUBLIC_ACCESS }
        - { path: ^/users$, methods: [POST], roles: PUBLIC_ACCESS }
        - { path: ^/, roles: IS_AUTHENTICATED_FULLY }
````

- `JwtAuthenticator` (`src/Security/Infrastructure/Symfony/JwtAuthenticator.php`) reads the `Authorization: Bearer <token>` header and decodes it with `TokenEncoderDecoder` — the same service `POST /login` and `PUT /token-renew` use to issue access tokens.
- `AppUserProvider` (`src/Security/Infrastructure/Symfony/UserProvider/AppUserProvider.php`) resolves the decoded `id` claim to an `App\User\Domain\Model\User` via `UserRepository::getById()`.
- Everything not explicitly listed in `access_control` requires a valid, non-expired access token.

Any endpoint that should stay public needs its own `access_control` entry, matched before the catch-all `IS_AUTHENTICATED_FULLY` rule.

## Login

`POST /login` (`UserAuthenticationController`) takes an email and password and returns an access token plus a refresh token. No `Authorization` header is needed for this call.

Request:

````bash
curl -X POST http://localhost/login \
  -H "Content-Type: application/json" \
  -d '{
    "email": "user@example.com",
    "password": "secret123"
  }'
````

Response `200`:

````json
{
  "accessToken": "eyJ0eXAiOiJKV1QiLCJhbGciOiJSUzI1NiJ9...",
  "refreshToken": "a3f1c9...<opaque refresh token>"
}
````

`accessToken` is the RS256 JWT issued by `TokenEncoderDecoder` with the user's `id` as payload claim. `refreshToken` is an opaque value generated by `RefreshTokenGenerator` and persisted (`RefreshToken` / `DoctrineRefreshTokenRepository`) so it can be revoked or renewed later.

Possible errors: `401` (`BadCredentialsException`, wrong email/password), `403` (`InactiveUserException`, user disabled), `429` (`TooManyAttemptsException`, rate-limited by `LoginRateLimiter` per IP and per email).

## Calling a private/secured endpoint

Every route not explicitly whitelisted in `access_control` requires `IS_AUTHENTICATED_FULLY`. Send the `accessToken` from login as a Bearer token in the `Authorization` header on every request:

````bash
curl -X GET http://localhost/users/9c858901-8a57-4791-81fe-4c455b099bc9 \
  -H "Authorization: Bearer eyJ0eXAiOiJKV1QiLCJhbGciOiJSUzI1NiJ9..."
````

`JwtAuthenticator` reads that header, decodes the token with `TokenEncoderDecoder`, and resolves the `id` claim to a `User` via `AppUserProvider`. If the header is missing, malformed, or the token is invalid/expired, the request is rejected with `401`:

````json
{
  "type": "security.unauthenticated",
  "message": "Authentication required.",
  "params": [],
  "status": 401
}
````

## Renewing the access token

Access tokens are short-lived. Before (or after) one expires, exchange the refresh token for a new pair via `PUT /token-renew` (`RenewUserAuthenticationController`):

````bash
curl -X PUT http://localhost/token-renew \
  -H "Content-Type: application/json" \
  -d '{
    "token": "a3f1c9...<refreshToken from login>"
  }'
````

Response `200` — same shape as login, and both tokens are rotated (a new refresh token is issued, invalidating the old one):

````json
{
  "accessToken": "eyJ0eXAiOiJKV1QiLCJhbGciOiJSUzI1NiJ9...",
  "refreshToken": "b7e2d4...<new refresh token>"
}
````

Possible errors: `401` (`InvalidTokenException` / `ExpiredTokenException`), `429` (`TooManyAttemptsException`).

## Logout

`DELETE /token-renew` (`LogoutController`) revokes a refresh token so it can no longer be used to renew access:

````bash
curl -X DELETE http://localhost/token-renew \
  -H "Content-Type: application/json" \
  -d '{
    "token": "a3f1c9...<refreshToken to revoke>"
  }'
````

Response `200`: `{}`. This only invalidates the refresh token — an already-issued access token stays valid until it expires, since access tokens are not stored/checked against a revocation list.
